# 자율 마무리(Autonomous Finish) 요구사항 — 👤 2026-09-02 원문 요약 (구현 대상 SoT)

목표: 비개발자가 범위·우선순위·완료 기준을 쓰지 않아도, 하네스가 BMAD 산출물 + 실제 구현 상태를 분석해 남은 작업을 스스로 계획하고 「배포 가능한 상태」까지 자율 완주. 트리거 예: 「baroos 프로젝트의 현재 상태를 파악하고 배포 가능한 수준까지 자율적으로 마무리해줘.」
구분: 「배포 가능한 상태 완성」 ≠ 「커밋·푸시·병합·배포」 — 외부 반영은 반드시 사용자 승인.

역할: BMAD = 요구·에픽·스토리·상태 방법론(대체·우회 금지 · 모든 변경은 기존 스토리에 연결하거나 새 스토리/결함 작업 등록) · Fable = 분석·우선순위·의존성·병렬화·배치 결정 오케스트레이터 · auto-story-finish = create→dev→review→QA 실행 엔진 · night-batch-ops = 격리·병렬·통합·실패 복구·안전 중단 · Claude/Codex = 구현·테스트·분석·교차 리뷰 작업자.

1. 프로젝트 자동 진단 — PRD/Architecture/에픽/스토리/상태/완료기준 · 코드·테스트·빌드·실행 상태 · 최근 변경·미커밋 · 미완 기능·임시 코드·비활성 테스트 · 보안/성능/접근성/데이터 위험 · 배포 차단 · 문서-구현 불일치. 문서의 완료 표시 불신 — 판정 우선순위: **실제 실행 결과 → 테스트 → 코드 → BMAD 스토리 → 계획 문서**.
2. 범위·우선순위 자동 결정 — 완료/부분/누락/결함/테스트 부족 분류. 작업마다: 목적·사용자 영향 · 연결 에픽/스토리 · 완료 기준 · 위험도·우선순위 · 선행·의존성 · 병렬 가능 여부 · 필요 테스트·게이트 · 구현자·교차 리뷰어. 우선순위 7단계: ①비밀정보 노출/데이터 손실/인증·보안 ②빌드 실패/실행 불가/핵심 장애 ③배포 차단 ④핵심 흐름 미완 ⑤회귀·테스트 누락 ⑥성능·안정성·접근성 ⑦내부 구조·문서. 새 문제 발견 시 계획·우선순위 자동 갱신.
3. BMAD 흐름 유지 — 코드부터 고치지 않는다: ①기존 에픽/스토리 포함 여부 ②있으면 상태·완료기준 보완 ③없으면 적절한 에픽에 새 스토리/결함 작업 생성 ④의존성·완료기준 작성 ⑤create→dev→review→QA ⑥검증 증거 충족 시에만 Done. 기존 문서·번호·연결·템플릿·사용자 변경 보존. 완료 후 BMAD 기록에 구현 내용·변경 파일·테스트·리뷰·남은 위험·미검증 반영.
4. Fable 오케스트레이션 — 미완 탐색 · 분해·DAG · 우선순위 · Claude/Codex 동적 배치 · 병렬/순차 · 충돌 관리 · 교차 리뷰 편성 · 실패 분류·수정 루프 통제 · 계획 갱신. **홀짝·단순 교대 배정 금지** — 난이도·위험도·제공자 적합도·가용성. 설계·보안·복잡 오류 = 강한 모델 / 독립 테스트·문서·정형 = 빠른 모델. 구현자≠리뷰어 제공자.
5. 병렬·자동 수정 — 선행 없음·파일 충돌 낮음·독립 검증 가능만 병렬. 보수 처리: 인증·결제·권한 / DB 변경 / 배포 설정 / 공용 인터페이스 / 공유 핵심 파일 / 비밀정보·외부 연동. 실패 분류 = 환경·코드·테스트·보안·성능·통합 → 실패 범위만 수정 → 관련 테스트 + 전체 회귀. 반복 실패·위험 증가 시 안전 중단 + 근거·선택지 보고.
6. 질문 최소화 — 코드·문서·테스트·기존 결정으로 판단 가능한 기술 사항은 묻지 않음. 질문 허용: 제품 의도 다의 / UX·사업 방향 / 데이터 삭제·비가역 / 유료·비용 / 계정·인증·비밀정보 / 법률·정책 / 외부 공개·발송 / 커밋·푸시·병합·배포 승인. 질문 형식: 비개발자 언어 · 차이 설명 · 추천안·이유·대안·안전 기본값. 대기 중에도 독립 작업 계속.
7. 완료 기준 — 작업: 기능·흐름 정상 · 정상/실패/경계 테스트 · 전체 회귀 · 보안/성능/통합 게이트 · 테스트 삭제/skip/only/완화/우회 없음 · 다른 제공자 교차 리뷰 통과 · BMAD 상태=코드 상태 · 실행 증거+미검증 기록. 프로젝트 「배포 가능」: 핵심 흐름 실동작 · 높음·중간 차단 0 · 빌드/테스트/보안/성능/통합 GREEN · 필수 에픽·스토리=구현 일치 · 미완 0 또는 사용자 후속 승인 · 문서=동작 · 최종 교차 리뷰 통과 · 미확인을 통과로 표시 금지.
8. 안전 경계(승인 없이 금지) — main/보호 브랜치 직접 작업 · 커밋/푸시/병합/배포 · 실패 강제 반영 · 게이트 생략 · 사용자 변경 덮어쓰기 · 허용 밖 파일 · 비밀정보 모델 입력/로그/보고서 · 파괴적 데이터 변경 · 무제한 재시도. 격리 worktree · 비밀 차단/격리 실패 시 중단 · 통합 RED 푸시 불가 · argv 분리 · 원자 슬롯.
9. 측정 — 전체·작업별 시간 · 병렬률·유휴 · 첫 시도 통과율 · 리뷰 결함 수 · 자동 수정·반복 실패 · 통합 실패율 · 순차 대비 절약 추정. 게이트 축소 금지.
10. 사용자 보고(비개발자 언어) — 할 수 있는 것 · 완료 기능/해결 문제 · 테스트/보안/성능/통합 · 확인한 사용자 흐름 · 자동 수정·교차 리뷰 · 시간·병렬 효과 · 남은 문제·위험 · 미검증 · 배포 가능 여부 · 최종 결정 필요 항목.

구현·검증: 두 스킬에 실제 구현 + 테스트 + 문서. Claude 단독·단일 스토리·기존 안전장치 하위 호환. 전체 테스트 + 실제 사용 흐름 검증 + Codex 적대 교차 리뷰 → 높음·중간 전부 해결 후 재검증. 최종 보고 = 완전/부분/미구현 구분 + 실행 증거. 커밋·푸시·병합·배포·운영 엔진 교체는 승인 전 금지.
