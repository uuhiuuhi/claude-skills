# my-todo — 사람 몫 한 장

24시간 러너는 결정·회수·목업을 가능한 한 스스로 푼다. 그래도 **사람만 할 수 있는 것**이 남는다 — 되돌릴 수 없는 실행, 스토리가 스스로 남긴 질문, 사람 게이트 작업, 자율 한계, AI 결정·AI 목업의 사후 확인.
이 스킬은 그것을 **한 번에 모아** 비개발자가 5~10분 안에 답할 수 있게 만들고, 답을 받으면 반영까지 한다.

## 먼저 정하는 값

값의 읽는 순서·기본값은 [references/parameters.md](references/parameters.md)가 정본이다. 이 스킬이 쓰는 것:
`HUMAN_TITLE`(기본 「👤 내 차례」) · `RUNNER` · `STATE` · `TASK` · `ART` · `INBOX` · `RELEASE_LOG` · `BASE`(기본 `main`) · 목업 판정 파일(`mockupGate.verdictsPath` · 기본 `tools/dev-status/mockup-verdicts.json`).

```bash
( source ~/.claude/skills/batch-24-multiAG/ops/lib.sh && echo "RUNNER=$RUNNER STATE=$STATE TASK=$TASK" )
```

명령 속 `$BASE` 같은 이름은 위 값으로 바꿔 넣는다. 설정이 없으면 「배치 설정 없음」이라 적고, 저장소 안 재료(인박스·스토리 파일)만으로 계속한다.

## 1. 저장소·상태 정렬

```bash
git fetch --all --quiet; git status -sb; git branch -r --no-merged origin/$BASE | grep auto/
```

- 미머지 `auto/*` 가 있으면 최신 산출물은 그 갈래에 있다 — 스토리·인박스는 `git show origin/auto/<최신>:<경로>` 로 읽는다.
- 러너가 도는 중인지(`STATE/runner.lock`)를 먼저 본다 — 4절 반영 방법이 달라진다.

## 2. 재료를 읽는다 (전부 · 없으면 「없음」이라 적는다)

| 무엇 | 어디 | 어떻게 읽나 |
|---|---|---|
| **사람 몫 파일** | `STATE/human-gates.json` | `humanGates[]` = `{key, type: question·gate·post-hoc, text}` · `excluded[]`(편성에서 빠진 스토리와 사유) · `unmergedBranches[]` · `chainAgeDays` · `at`. **`at` 이 1시간 넘었으면** `node tools/auto/plan-queue.mjs --dry` 로 새로 만든다 |
| **AI 결정 사후 확인** | `INBOX` 의 「사후 확인」 절 | 결정마다 무엇/선택/근거/대안/되돌리는 방법. **되돌리기 비싼 것**(DB 반영·정책·외부에 보이는 문구)만 개별로, 나머지는 묶음 |
| **결정 대기** | `INBOX` 의 「결정 대기」 절 | 오래 기다린 순서. 자율 모드(`autonomy.mode = full`)면 다음 라운드가 추천안을 채택할 예정이라고 알리고, 지금 답하면 그 답이 우선한다 |
| **사람 질문** | 스토리 파일의 `BLOCKED-ON-HUMAN:` 줄(취소선 없는 것) | 질문 원문 + 「풀리는 조건」 그대로 |
| **사람 게이트 작업** | 스토리 파일 Tasks 절의 `- [ ]` 중 「사람 게이트」·「승인자」·👤 표기 | 운영 DB 적용 · 테스트 계정 · 비밀값 등록 · 실기 확인 등 |
| **AI 목업 사후 확인** | 목업 판정 파일의 `verdict: pending` | 파일 경로 → 열어 보고 approved/rejected 로 답하게 |
| **승인 대기(되돌릴 수 없는 실행)** | 미머지 `auto/*` · `RELEASE_LOG` 의 배포 후보 · 운영에 아직 없는 DB 변경 | 실행은 프로젝트가 정한 지시 문구로만(4절 아님) |
| **앞으로 필요한 것** | 최신 `STATE/auto-queue-*.json` 의 `batches[]` 와 그 스토리 파일 | 곧 돌 스토리에 사람 게이트·외부 계정·키·새 화면(목업 대상)이 있으면 **미리** 올린다 |

스크립트(`plan-queue.mjs` · `story-ledger.mjs`)는 batch-24-multiAG 설치본이 제공한다. 없으면 그 행은 「확인 못 함 — 편성 도구 없음」이다. **재료가 없는데 「할 일 없음」이라 쓰지 않는다.**

## 3. 한 장으로 낸다 (`HUMAN_TITLE` 절 형식)

순서는 **「지금 답하면 러너가 더 도는 것」이 먼저**다. 항목마다 **무엇을 / 왜 필요한지 / 안 하면 어떻게 되는지 / ⭐추천안**을 비개발자 기준 한두 문장으로. 선택지가 여럿이면 장단점 표. 번호를 붙이고 답 형식을 한 줄로 안내한다(예: 「전부 추천대로」 · 「1 가 · 3 나 · 5 나중에」).

1. **러너를 여는 답** — 자율 한계(question) · BLOCKED-ON-HUMAN · 사람 게이트 작업. 각각 추천안 1개.
2. **사후 확인** — AI 결정(비싼 것 개별 · 나머지 묶음) · AI 목업(approved/rejected).
3. **승인 항목** — 병합 · 배포 · 운영 DB · 외부 발송. 여기서는 **올리기만** 한다. 무엇을 누가 실행하는지는 프로젝트 CLAUDE.md 의 위임 규칙을 읽어 적는다(위임을 가정하지 않는다).
4. **앞으로 필요한 것** — 다음 1~2일 안에 사람이 준비해야 할 것(계정·키·외부 회신·실기 확인).
5. **잔재 정리(급하지 않음)** — 오래된 임시 보관(stash)·옛 갈래·빈 폴더.

건수가 0인 절은 한 줄로 「없음」. **전부 0이어도 다음 작업 추천 1가지는 항상 낸다**(「더 하실 일 없음」은 프로젝트가 완성된 날에만 쓴다).

## 4. 답을 받으면 그 자리에서 반영한다

- **AI 결정 번복** → 해당 스토리의 AI 결정 줄을 `- [ ] [Review][Decision] …` 로 다시 열고 사람 선택을 `✅ 확정(날짜 · 선택)` 으로 적는다 → 다음 편성이 다시 계획 단계로 집는다. 인박스 절 제목에 「✅ 번복 반영」.
- **사람 질문 답** → `BLOCKED-ON-HUMAN: …` 줄을 `~~…~~ — ✅ 해소(날짜 · 답)` 로 닫고, 답이 작업을 요구하면 Tasks 절에 적는다.
- **사람 게이트 작업 완료** → 그 줄을 `- [x]` 로 닫는다. 👤 표기는 근거 인용에만 남긴다 — 편성기가 열린 작업 줄의 👤 를 「사람 대기」로 읽어 편성에서 뺀다.
- **목업** → 판정 파일의 verdict 를 approved/rejected 로, note 에 날짜·이유.
- 반영 뒤 `node tools/auto/plan-queue.mjs --dry` 로 **풀렸는지 실측**한다(`?` 줄이 줄었는지).
- **어디에 쓰나**: 사람 작업 폴더에서 고친다. 러너가 미머지 `auto/*` 위에서 돌고 있으면 그 갈래에 반영해야 러너가 본다. **러너가 도는 동안 러너 폴더·기준 갈래에 직접 쓰지 않는다** — 러너 폴더 반영은 batch-24-multiAG `ops/gap-apply.sh` 로 라운드 경계에서 한다(왜: 도는 워커가 남의 변경을 자기 커밋에 쓸어 담거나, 원격 변화를 오인해 멈춘다).
- **커밋·푸시**: 프로젝트 규칙을 따른다(문서 전용 변경의 즉시 커밋이 허용된 프로젝트면 커밋 · 아니면 변경만 하고 묻는다).
- 러너가 쉬고 있으면 `runner-start` 스킬로 깨운다(Windows: `Start-ScheduledTask -TaskName "$TASK"` · 중복 기동은 lock 이 막는다).

## 보고 형식

진행 보고(쉬운 말 · 결론 먼저 · 짧게)를 위에, `HUMAN_TITLE` 절을 맨 아래에. 반영한 것은 「무엇을 어떻게 바꿨고, 편성에서 몇 건이 풀렸는지」 한 줄씩.
백그라운드 작업을 띄우면 batch-24-multiAG SKILL.md 「백그라운드 작업 표기 규칙」(`[지금작업중·<모델>]` · `[지금감시중]` · `[지금확인중]` · 시한)을 따른다.

## 하지 않는 것

- 기준 갈래 병합·푸시·운영 배포·운영 DB 쓰기·외부 발송·삭제·인증정보 — 승인 항목으로 올릴 뿐이다. 실행은 프로젝트가 정한 지시 문구·위임 범위 안에서만, 이 스킬 밖에서 한다.
- 재료가 없는데 「할 일 없음」이라 쓰기 — 사람 몫 파일이 없으면 「사람 몫 파일 없음(편성 미실행)」이라 적고 `plan-queue.mjs --dry` 로 만든다.
- 사람 대신 결정하기 — 추천은 하되 확정은 사람의 답으로만.
